## 1. 목표 구조: 4개 레이어

LLM이 하는 일을 **방향과 확신도**로 제한하고, 나머지는 결정론적 룰로 닫는다. Lean의 Algorithm Framework 5단계와 ai-hedge-fund의 "LLM은 주문에 관여하지 않는다"(README L142-143) 원칙을 합친 형태다.

```
[1 유니버스 선별]  결정론 필터 → 후보 10~20개          (freqtrade Pairlist + Lean QC500)
        ↓ ScreenRun 기록 (audit.py)
[2 에이전트 판단]  후보별 Insight {direction, confidence, period, thesis, evidence}
        ↓ DecisionRecord 기록, REVIEW 격리            (agent_trading_core)
[3 하드 룰]        포지션 한도·섹터·손절·트레일링·Protections → 목표 비중
        ↓                                           (Lean Risk + freqtrade Protections + AHF limits)
[4 실행]           델타 주문, no-trade band, ADV 캡, 매도 우선, 스프레드 조건
                                                    (AHF execution + Lean Spread/VWAP)
        ↓
[정산·반성]        보유기간 뒤 알파 계산 → 교훈 → 다음 [2]에 주입   (agent_trading_core.memory)
```

### 2-2. Lean 유니버스 (`Algorithm.Framework/Selection/`)

- **QC500** (`QC500UniverseSelectionModel.py`): 월 1회만 재선별(36-37). 1단 = `has_fundamental_data and volume>0 and price>0` → 달러거래량 상위 1000(39-40). 2단 = 본사 USA, NYSE/NASDAQ, IPO 180일 초과, `market_cap > 5e8`(59-62) → **섹터별 비례 쿼터**로 달러거래량 상위 500(79-85).
- 예시: `price > 1` → 거래대금 정렬 → PE 내림차순 상위 2 (`FundamentalUniverseSelectionAlgorithm.py` 73-80). EMA100 > EMA300×1.01 종목을 `(fast-slow)/mean` 순 500개 (`EmaCrossUniverseSelectionModel.py` 58-65).
- 코스 필드: `DollarVolume`, `Volume`, `HasFundamentalData` (`CoarseFundamental.cs` 35-45).

**이식**: 1단(유동성)·2단(품질)·섹터 쿼터·월 1회 구조를 그대로. 한국이면 거래소=KRX, IPO 180일, 시총 하한만 치환. **LLM 호출 수를 제한하는 비용 통제 장치**로도 작동한다.

### 2-3. qlib 유니버스 정의

- `instruments/<market>.txt`: `symbol \t start \t end` 행으로 **편입/편출 기간을 보존**(`scripts/data_collector/index.py` 235-237). 백테스트 생존편향 방지의 정석.
- `qlib/data/filter.py`: `ExpressionDFilter('$close/$open>5')`, `'$rank($close)<10'` 같은 식으로 날짜별 동적 필터(312-375).

**이식**: 유니버스를 "오늘의 리스트"가 아니라 "기간이 있는 행"으로 저장하는 스키마만 빌린다.

### 2-4. 설계안: 선별 규칙 초안

```
universe: KOSPI200 + KOSDAQ150  (편입/편출 기간 보존)
rules (순서대로, 각 단계 통과/탈락을 FilterResult로 기록):
  1. price_min            종가 ≥ 1,000원
  2. listed_days_min      상장 ≥ 180일
  3. dollar_volume_top_n  20일 평균 거래대금 상위 100
  4. volatility_band      20일 변동성 연율 15%~80%
  5. range_stability_min  60일 고저폭/저가 ≥ 5%
  6. sector_quota         섹터당 최대 3종목
  7. performance_filter   메모리 로그 최근 10건 평균 알파 < -3% 종목 제외
  → 상위 15개 → 에이전트
refresh: 1·3·4·5 매일, 2·6 주 1회, 7 정산 시마다
```

## 3. 레이어 2: 에이전트 판단 계약

### 3-1. Lean Insight (`Common/Algorithm/Framework/Alphas/Insight.cs`)

필드: `Symbol`(71) `Direction` Up/Flat/Down(91) `Period`(96) `Magnitude` nullable(101) `Confidence` nullable(106) `Weight` nullable(111) `Tag`(126) `SourceModel`(49). **Period 만료 시 포트폴리오 모델이 자동으로 0 타깃**(`PortfolioConstructionModel.cs` 133-138). 내장 알파(EMA/MACD/RSI)는 Direction·Period만 채우고 Confidence는 비운다.

### 3-2. ai-hedge-fund 시그널 (`hedge_fund/signals/llm_agent.py`)

출력 JSON `{signal: bullish|neutral|bearish, confidence 0-100}` 검증(158-176) → `value = sign × confidence/100`(187). LLM 호출/파싱 실패 → `value 0, abstained=True`(207-215). 데이터 오류는 전파. 백테스트는 `blind=True`로 티커·날짜·금액을 가린다(58-63). 입력은 TTM 20분기 스냅샷(`features/snapshot.py` 39-72).

### 3-3. 설계안: Insight 스키마

TradingAgents의 `PortfolioDecision`(5단계 등급)과 Lean Insight를 합친다. 코어의 `schemas.py`는 그대로 쓰고, 하드 룰로 넘길 때 다음으로 변환한다.

```
direction   = {Buy, Overweight: +1 / Hold: 0 / Underweight, Sell: -1}
confidence  = {Buy, Sell: 1.0 / Overweight, Underweight: 0.5 / Hold: 0}  또는 LLM이 직접
period      = PortfolioDecision.time_horizon (없으면 기본 holding_period_days)
REVIEW      = abstain. 비중 0, 사람 확인 큐.
```

**빌릴 것**: Period 만료 → 자동 청산(LLM이 "팔아라"를 잊어도 포지션이 닫힘), abstain=0, blind 백테스트, 입력 스냅샷 해시로 프롬프트 캐시.
**빌리지 말 것**: Magnitude(수익률 예측치). LLM의 숫자 예측은 신뢰도가 낮아 MVO·BlackLitterman류 최적화는 과설계.

## 4. 레이어 3: 매수·매도·청산 하드 룰

### 4-1. freqtrade 청산 체계 (`freqtrade/strategy/interface.py`)

- **청산 판정 순서** `should_exit`(1419-1520): `exit_signal/custom_exit → stop_loss/liquidation → ROI → trailing`. `exit_profit_only`면 수익 중일 때만 신호 청산(1495).
- **ROI 표** `min_roi_reached_entry`(1675-1731): `{보유분: 수익률}`에서 `key ≤ 보유시간` 중 최대 key 선택, `current_profit > roi`면 청산. 샘플 `{"60":0.01, "30":0.02, "0":0.04}` = 즉시 4%, 30분 후 2%, 60분 후 1%면 청산. custom_roi와 둘 중 낮은 값(1711).
- **트레일링** `ft_stoploss_adjust`(1524~): 고점 추적, `bound_profit > trailing_stop_positive_offset`일 때 `trailing_stop_positive` 비율로 교체(1596-1604). `trailing_only_offset_is_reached`면 오프셋 전엔 미갱신.
- **훅**: `confirm_trade_entry(...)->bool`(359), `confirm_trade_exit(...)->bool`(395), `custom_stoploss(...)->float`(446, `self.stoploss`보다 느슨해질 수 없음), `custom_exit(...)->str|bool`(594, 문자열 = 청산 사유 태그), `custom_stake_amount(...)`(625), `adjust_trade_position(...)`(654, 분할 매수·부분 청산).
- **청산 사유 열거** `enums/exittype.py`(9-20): `roi, stop_loss, stoploss_on_exchange, trailing_stop_loss, liquidation, exit_signal, force_exit, emergency_exit, custom_exit, partial_exit, sold_on_exchange`.
- 사이징: `stake_amount` 또는 `"unlimited"` = `(가용+묶인금액)/max_open_trades`(wallets 357-359), `tradable_balance_ratio=0.99`, `amount_reserve_percent=0.05`, `max_open_trades`.

**이식**: 청산 우선순위·ROI 표(단위를 분 → 거래일로)·트레일링 상태기계·ExitType을 **그대로**. LLM 판단은 `confirm_trade_entry` 거부권과 `custom_exit` 사유 문자열 자리에 끼운다. `leverage`, `liquidation`, `stoploss_on_exchange`, 24시간 전제 기본값은 버린다.

### 4-2. freqtrade Protections (`freqtrade/plugins/protections/`)

공통 파라미터(`iprotection.py` 40-53): `stop_duration_candles` / `lookback_period_candles` / `unlock_at "HH:MM"`. 결과는 전역·종목·방향 잠금(PairLocks).

| Protection | 규칙 | 기본값 |
|---|---|---|
| StoplossGuard (54-74) | lookback 내 손절·트레일링 청산 건수 ≥ `trade_limit` → 잠금 | 10건, `only_per_pair=False` |
| MaxDrawdown (54-96) | 거래수 ≥ `trade_limit`, 누적 DD > `max_allowed_drawdown` → 전역 잠금 | mode `ratios`|`equity` |
| CooldownPeriod (28-53) | 종목 마지막 종료 후 lookback 내 재진입 금지 | |
| LowProfitPairs (64-69) | 종목별 수익률 합 < `required_profit` → 종목 잠금 | |

**이식**: 4종 **그대로**. "연속 손절 뒤 거래 중단"은 LLM 시스템에서 특히 중요하다(모델이 한 방향으로 쏠릴 때 끊어주는 유일한 장치). 단위를 거래일로.

### 4-3. Lean Risk 모델 (`Algorithm.Framework/Risk/`, 기본값)

| 모델 | 규칙 | 기본 |
|---|---|---|
| MaximumDrawdownPercentPerSecurity (37-45) | 종목 미실현 −X% → Insight 취소 + 0 타깃 | 5% |
| TrailingStopRiskManagementModel (53-66) | 보유가치 고점 대비 X% 하락 → 청산 | 5% |
| MaximumSectorExposure (69-74) | 섹터 X% 초과 시 비율 축소(청산 아님) | 20% |
| MaximumUnrealizedProfitPerSecurity (38) | +X% 익절 | 5% |
| MaximumDrawdownPercentPortfolio (42-59) | 포트폴리오 DD. 주의: **이번 틱 전달된 targets만** 처리(47), 보유 전량 청산이 아님 | 5%, trailing False |

### 4-4. ai-hedge-fund 리스크 클램프 (`hedge_fund/risk/limits.py`)

적용 순서(140-148): 종목별 `|w| ≤ max_position` → 넷 밴드 → 섹터 → 베타 → 변동성 → **드로다운 반감(×0.5)** → 그로스. 축소분은 현금 유지(8-10). 예시(`fund/example.yaml` 29-37): 종목 25%, 그로스 1.0, 피크 대비 −10% 반감, **−20% 전량 청산 후 현금 유지**(`session.py` 183-185), 주문 ≤ ADV20의 5%.

**이식**: 7단계 순서와 "DD −10% 반감 / −20% 스톱아웃"을 **그대로**.

### 4-5. 포트폴리오 구성

- **Lean ConfidenceWeightedPCM**(`Portfolio/ConfidenceWeightedPortfolioConstructionModel.py` 44-52): confidence를 비중으로, 합 > 1이면 비례 축소, `PortfolioBias.Long`으로 롱온리. **LLM이 confidence를 채울 수 있으므로 가장 직접 맞는 규칙.**
- **qlib TopkDropoutStrategy**(`qlib/contrib/strategy/signal_strategy.py` 74-294): 보유 ∪ 신규후보를 점수순 정렬 → 매도 = 보유 중 하위 `n_drop` → 매수 = 그만큼 상위 신규. **보유보다 낮은 점수 신규를 사는 일 방지**(219). `hold_thresh`(최소 보유일), `risk_degree=0.95`, 상하한·정지 종목 거래 금지(231-237), 동일가중(265). LLM 랭킹 점수를 signal로 넣으면 바로 동작.
- **AHF construction**(`portfolio/construction.py` 29-105): `conviction = Σwᵢvᵢ/Σwᵢ`(abstain 제외), `weight = score/Σ|score| × gross_target`.

**이식**: 롱온리 소수 종목이면 ConfidenceWeighted, 랭킹 교체 전략이면 TopkDropout. 둘 중 하나.

## 5. 레이어 4: 실행

- **AHF `pipeline/execution.py`**(16-74): `target_shares = int(w·equity/mark)` 내림 → 보유와 차이로 delta → 증액이 `min_trade_pct(0.5%)×equity` 미만이면 skip, **축소·청산은 항상 실행** → `max_adv_pct×ADV` 수량 캡 → **매도 먼저, 매수 뒤**. T 종가 판단 → T+1 체결, 체결 전 재평가(`stages.py` 142-158). `validation.py`가 신호부터 재계산해 불일치 시 raise.
- **Lean Execution**: Spread(스프레드/가격 ≤ 0.5%, 장중만, 58-60), VWAP(매수는 bid < 일중 VWAP, 봉 거래량 1% 상한, 90-95), StdDev(60분 SMA ± 2σ 유리할 때만, 주문당 $20,000, 103-108). Immediate는 마진영향 순 시장가.
- **qlib exchange**(`qlib/backtest/exchange.py` 38-51, 285-291, 894-948): `open_cost 0.0015, close_cost 0.0025, min_cost 5`, `limit_threshold`로 상하한 종목 매수·매도 금지, 정지 = close NaN, `trade_unit` 반올림, `cost_ratio = cost + impact·(trade_val/일거래대금)²`, volume_threshold로 체결량 클립.

**이식**: AHF 델타 주문 전체 + Lean Spread 조건 + qlib 비용·상하한 모델. 한국은 `trade_unit 1`, `limit 0.30`, 수수료·거래세만 교체. T/T+1 분리는 TradingAgents 정산(첫 종가 진입)과 일관된다.

## 6. 백테스트·채점

- **TradingAgents**(추출 완료): 등급별 알파·방향 적중률, REVIEW는 미채점, 보유기간 첫 종가 진입, 시점 필터된 교훈.
- **qlib 라벨** `Ref($close,-2)/Ref($close,-1)-1`(익일 종가 매수 → 익익일 수익): 실행 시차를 라벨에 반영하는 정석. 채점 기준일을 이와 맞출 것.
- **qlib Alpha158**(`contrib/data/loader.py`): kbar 9 + 가격 4 + 롤링 29연산×5창 = 158 팩터. 대표식 `KMID=(close-open)/open`, `RSV=(close-Min(low,d))/(Max(high,d)-Min(low,d))`, `SUMP=Σmax(Δclose,0)/Σ|Δclose|`, `CORR=Corr(close, Log(volume+1), d)`, `WVMA=Std(|ret|·vol)/Mean(|ret|·vol)`. 표현식 엔진 없이 pandas로 재구현해 선별 점수나 에이전트 입력 피처로.
- **AHF scorecard**: 전략 가중치를 t-stat으로 `mandate × clip(1+0.25·t, 0.25, 2.0)`, 최소 20표본(`fund/example.yaml` 43-47). 에이전트 종류별 가중치 자동조정 아이디어.

## 8. 구현 순서 제안

1. **선별 레이어**: 2-4 규칙 7개를 pandas로. 매 단계 `FilterResult` 기록 → `ScreenRun` 저장.
2. **하드 룰 레이어**: freqtrade 청산 우선순위 + ROI 표 + 트레일링 + Protections 4종 + Lean Composite(DD/Trailing/Sector) + AHF DD 반감·스톱아웃. 전부 단위 테스트 가능.
3. **에이전트 레이어**: `agent_trading_core`로 접지 → 결정 → REVIEW 격리 → `DecisionRecord`.
4. **실행 레이어**: AHF 델타 주문 + 증권사 API. 처음엔 페이퍼 트레이딩.
5. **채점**: 매일 `settle_all_pending`, 주 1회 `summarize`. PerformanceFilter가 이 결과를 다시 선별에 반영.

하드 룰(2)을 에이전트(3)보다 먼저 만드는 이유: LLM 없이도 규칙만으로 백테스트가 돌아야 "에이전트가 규칙 대비 알파를 더하는가"를 측정할 수 있다.

## 10. 실무 관점 평가: 이 규칙들은 실제 운용에서 쓰이는가

오픈소스에서 빌린 규칙을 **기관 시스템 운용에서 표준인 것 / 개인·봇 트레이딩 수준인 것 / 근거가 약한 것**으로 나눈다. 아래는 재무 문헌과 업계 관행에 근거한 평가이며, 특정 펀드의 내부 규칙을 확인한 것은 아니다.

### 10-1. 기관 표준에 해당 (그대로 써도 됨)

| 규칙 | 근거 |
|---|---|
| 유동성·시총·상장기간·가격 하한으로 유니버스 구성 (Lean QC500, freqtrade Volume/Age/Price) | 지수 편입 기준(S&P·Russell)과 퀀트 펀드 유니버스 구성 방식이 정확히 이 구조. 거래대금 상위 N은 체결 가능성 확보의 기본 |
| 종목 한도·섹터 한도·그로스/넷 노출·드로다운 단계별 축소 (AHF limits, Lean Risk) | 헤지펀드 리스크 정책의 표준 항목. "피크 대비 −10% 반감, −20% 현금화"는 전형적인 드로다운 트리거 |
| 랭킹 기반 리밸런싱 + 완충 구간 (qlib TopkDropout의 comb·hold_thresh) | 롱온리 팩터 펀드의 교체 방식 그 자체. 상위 분위 매수, 완충 구간 이탈 시 매도로 회전율 통제 |
| 참여율 상한(ADV %), 제곱근 충격비용, VWAP 조건, 매도 선행 (AHF execution, Lean VWAP/Spread, qlib exchange) | 기관 실행 알고리즘(Almgren-Chriss 계열, VWAP/TWAP)의 기본 가정 |
| 기간 만료 시 자동 청산 (Lean Insight Period) | "타임 스탑". 논지가 실현되지 않으면 자본을 회수하는 운용 규율 |
| 연속 손실·일일 손실 한도 후 거래 중단 (freqtrade Protections) | 프랍 데스크의 일일/주간 손실 한도(circuit breaker)와 같은 기능 |
| 판단일 T 종가 → T+1 체결, 룩어헤드 차단 | 백테스트 무결성의 최소 요건. 안 지키면 결과가 전부 무효 |

### 10-2. 개인·봇 트레이딩 수준 (쓸 수는 있으나 기관 관행은 아님)

| 규칙 | 평가 |
|---|---|
| 고정 % 손절 (freqtrade `stoploss=-0.10`) | 재량 운용 매니저는 잘 쓰지 않는다. 추세추종 CTA는 **ATR 배수 손절**(터틀 규칙: 2 ATR)을 쓴다. 학술 증거는 혼재: 추세 국면에서는 유효, 평균회귀 국면에서는 손해(Kaminski & Lo 2014). 고정 %보다 ATR 기반으로 바꿀 것 |
| 시간 감쇠 익절표 (ROI 테이블) | 봇 트레이딩 특유의 장치. 기관에서는 목표가·리밸런스 일정으로 대체. 단기 전략이면 유용 |
| 트레일링 스탑 | 추세추종 전략의 핵심 청산 수단(터틀: 10/20일 저점 이탈). 기관 CTA도 사용. 단, 변동성에 비례한 폭(ATR)으로 |
| 지표 조합 진입 (RSI<30 + TEMA + 볼린저, `sample_strategy.py`) | **템플릿일 뿐 전략이 아니다.** 운용사가 이 조합을 그대로 쓰는 경우는 없다 |

### 10-3. 근거가 약한 것 ("차트 보는 법·매매법" 류)

지지·저항 되돌림, 눌림목, 캔들 패턴, 이평선 정배열 진입 같은 기법은 **학술 검증에서 거래비용 차감 후 초과수익 증거가 약하거나 재현되지 않는다**(Lo·Mamaysky·Wang 2000은 일부 패턴에 정보가 있으나 수익성은 미약, Park & Irwin 2007 서베이는 긍정 결과 다수지만 데이터 스누핑 우려 지적). LLM 에이전트에게 이런 기법으로 판단하라고 하면 그럴듯한 서술은 나오지만 채점하면 알파가 없을 확률이 높다.

차트 계열 중 기관급 근거가 있는 것은 하나다: **이동평균을 추세 필터로 쓰는 것**(200일선 위에서만 롱, Faber 2007 류의 타이밍). 진입 트리거가 아니라 **국면 필터**로 쓸 때만이다.

### 10-4. 조사 목록에 빠져 있는, 기관이 실제로 쓰는 것

| 항목 | 설명 | 적용 위치 |
|---|---|---|
| 팩터 점수 (모멘텀·가치·퀄리티·저변동성) | 12-1개월 모멘텀(Jegadeesh & Titman 1993), 가치·퀄리티(Fama-French, AQR). 수십 년 재현된 유일한 "선별 근거" | 선별 레이어 랭킹 점수. qlib Alpha158 수식 일부가 여기 해당 |
| 시계열 모멘텀 / 추세추종 | 자산 자체의 12개월 수익률 부호(Moskowitz·Ooi·Pedersen 2012) | 국면 필터 |
| 변동성 타게팅 / ATR 기반 사이징 | 종목별 변동성 역수로 비중, 포트폴리오 목표 변동성 유지 | 하드 룰 레이어. 고정 % 사이징 대체 |
| 회전율 완충 구간 | 상위 20%에 들면 매수, 40% 밖으로 나가야 매도 | TopkDropout의 hold_thresh를 확장 |
| 실적 발표 이벤트 처리 | 발표 전 보유 축소 또는 PEAD(실적 서프라이즈 후 드리프트) 활용 | 선별·청산 양쪽. AHF pead.py가 참고 |
| 리밸런스 캘린더 | 매일 아니라 주/월 단위, 신호가 임계 넘을 때만 거래 | 실행 레이어. 비용 통제 |

### 10-5. LLM 레이어에 대한 평가 (→ §12에서 수정됨)

LLM이 낸 재량 판단을 그대로 주문으로 보내는 운용사는 없다. TradingAgents 자체도 연구용이라고 명시한다. 현실적인 자리는 **"리서치 애널리스트"** 다: 뉴스·공시·실적을 읽고 방향과 확신도를 내면, 그것을 팩터 점수와 함께 **랭킹의 한 입력**으로 쓰고, 비중·손절·실행은 §10-1의 결정론 규칙이 맡는다. 그리고 §6의 채점으로 "LLM 입력을 넣었을 때와 뺐을 때 알파 차이"를 계속 측정해야 한다. 차이가 없으면 LLM은 비용만 쓰는 것이다.

### 10-6. 한국 시장에서 추가로 확인할 것

가격제한폭 ±30%, 변동성완화장치(VI), 거래세·수수료 체계, 공매도 가능 여부(제도 변경 잦음), 동시호가 체결 방식. qlib `limit_threshold`와 AHF 비용 모델에 이 값을 넣어야 백테스트가 맞는다. 이 항목들은 본 조사에서 확인하지 않았다.

### 11-4. 실측으로 보완 (할 일, 가장 중요)

문헌과 제도를 확인해도 "이 규칙이 KRX에서 지금 통하는가"는 알 수 없다. 그건 측정해야 한다. `agent_trading_core.backtest`가 이미 `decide(ticker, date)` 함수를 받으므로 다음 순서로 돌린다.

1. **규칙 전용 베이스라인**: 유동성 필터 + MSCI식 모멘텀 랭킹 + TopkDropout. LLM 없음. KOSPI200, 2023~2026, 주 1회 격자.
2. **LLM 추가**: 같은 격자에서 랭킹 상위 후보에만 에이전트 판단을 더함.
3. **비교**: 두 run의 `summarize()` 등급별 알파·적중률 차이. 차이가 통계적으로 없으면 LLM은 비용만 쓰는 것.
4. **룩어헤드 점검**: 뉴스·공시 피드는 "지금" 시점이라 2단계는 과거 날짜에서 완전 재현이 안 된다. 2024년 이후 구간은 페이퍼 트레이딩으로 전진 검증한다.

## 12. 방향 수정: LLM이 펀드매니저 역할을 한다 (2026-11-13)

목표가 분명해졌다. **운용사 없이 일반인이 바로 쓰는 시스템**이고, LLM이 **펀드매니저가 생각하는 흐름대로 판단해 매수·매도까지** 한다. 그러면 §10-5("LLM은 애널리스트 자리")는 철회하고 다음으로 바꾼다.

> LLM = 펀드매니저(재량 판단). 하드 룰 = 운용사의 리스크팀·운용 가이드라인(매니저도 그 안에서만 움직인다).

실제 운용사도 이 구조다. 매니저는 사고팔 자유가 있지만 종목 한도·섹터 한도·손실 한도·유동성 기준은 리스크팀이 정하고 매니저가 넘을 수 없다. 우리 시스템에서 그 리스크팀이 §4의 하드 룰이다. 즉 하드 룰은 LLM을 불신해서 두는 게 아니라, **매니저가 원래 살아가는 환경을 재현**하는 것이다.

따라서 §7에서 "비용 대비 효과 낮음"이라고 버린 TradingAgents의 불/베어 토론·리스크 3자 토론도 재평가한다. 그 토론은 운용사의 **투자위원회(IC)** 를 흉내 낸 것이고, 이 목표에서는 핵심 장치다. 유니버스 전체가 아니라 선별된 후보에만 돌리면 비용 문제도 해결된다.

### 12-1. 펀드매니저의 사고 흐름 (롱온리 주식, 재량 운용 기준)

운용 교육(CFA 커리큘럼)과 공개된 투자 메모 관행에서 공통으로 나오는 단계다. 각 단계가 에이전트의 어느 부분에 대응하는지 함께 적는다.

| 단계 | 매니저가 묻는 질문 | 에이전트 대응 | 코어 모듈 |
|---|---|---|---|
| 1 아이디어 발굴 | 왜 지금 이 종목을 볼 이유가 생겼나 (실적, 뉴스, 스크린, 가격 급변) | 선별 레이어 + 뉴스·실적 애널리스트 | `audit.ScreenRun` |
| 2 사업 이해 | 무엇으로 돈을 벌고, 경쟁우위는 무엇이고, 그게 유지되나 | 펀더멘털 애널리스트 | `identity`(정체 고정) |
| 3 실적·재무 점검 | 매출·이익 추세, 마진, 부채, 현금흐름. 숫자가 이야기와 맞나 | 펀더멘털 애널리스트 | DART 연동 예정 |
| 4 밸류에이션 | 지금 가격이 싸냐 비싸냐. 과거 자신·동종 대비 배수, 목표가, **상승여력 vs 하락위험 비율** | 리서치 매니저 | `InvestmentMemo.upside_pct / downside_pct` |
| 5 촉매와 시점 | 무엇이 언제 가격 갭을 닫나 (실적 발표, 신제품, 정책). 촉매 없으면 "싸지만 안 산다" | 뉴스 애널리스트 + 리서치 매니저 | `InvestmentMemo.catalysts, time_horizon` |
| 6 논지 반박 | 베어 케이스는 무엇이고 무엇이 틀리면 논지가 깨지나 | **불/베어 토론** | TradingAgents 리서처 |
| 7 리스크·사이징 | 확신도와 하락위험에 비례해 얼마나 담나. 포트폴리오 전체에서 이 종목이 차지할 비중 | 트레이더 + 리스크 토론 + 하드 룰 | `TraderProposal.position_sizing`, 리스크 클램프 |
| 8 진입 계획 | 한 번에 다 사나 분할하나, 어느 가격대에서 | 트레이더 | `TraderProposal.entry_price` |
| 9 모니터링·매도 | 논지가 깨졌나, 목표가에 왔나, 더 좋은 대안이 생겼나, 비중이 커졌나 | **매도 판단 에이전트(신설 필요)** + 하드 룰 | `InvestmentMemo.exit_plan`, Protections |
| 10 사후 검토 | 결과가 논지와 맞았나, 운이었나 실력이었나 | 정산·반성 | `memory.settlement/reflection` |

TradingAgents는 1~8·10을 갖고 있고 **9(보유 중 종목의 매도 판단)가 없다.** 그 파이프라인은 "이 종목을 지금 어떻게 보나"를 매번 새로 묻는 구조라서, 보유 종목에 대한 "팔 이유가 생겼나"를 따로 묻는 단계를 만들어야 한다.

### 12-2. 매니저가 실제로 쓰는 매수·매도 기준

차트 기법이 아니라 재량 운용 매니저가 투자 메모와 IC에서 쓰는 기준이다. 코드가 아니라 **프롬프트와 스키마에 넣어야 하는 것**이다.

**매수 (전부 충족해야 IC 통과)**
1. 사업을 두 문장으로 설명할 수 있다 (이해 못 하는 건 안 산다).
2. 상승여력/하락위험 비율이 최소 2:1, 통상 3:1. 목표가와 하락 시나리오 가격이 숫자로 있다.
3. 12개월 안에 갭을 닫을 촉매가 구체적으로 있다.
4. 베어 케이스를 서술할 수 있고, 그것이 왜 틀렸는지 답할 수 있다.
5. 논지가 깨지는 조건(invalidation)이 미리 적혀 있다. 가격이 아니라 **사실**로: "다음 분기 영업이익률이 X% 아래면".
6. 포트폴리오에 이미 같은 베팅(같은 섹터·같은 매크로 노출)이 있지 않다.

**매도 (하나라도 해당하면 검토, 두 개면 매도)**
1. 목표가 도달 → 상승여력이 하락위험보다 작아짐.
2. 논지 깨짐 → 미리 적어둔 invalidation 조건 충족. **가격 하락 자체는 이유가 아니다**; 사실이 변했는지 본다.
3. 더 좋은 대안 → 같은 리스크로 상승여력이 더 큰 종목이 나타남 (기회비용).
4. 비중 초과 → 올라서 한도를 넘음. 일부 매도로 원래 비중 복귀.
5. 촉매 소멸 → 기대했던 이벤트가 지나갔고 다음 촉매가 없음.
6. "오늘 처음 본다면 사겼나" 테스트에 아니오.
7. 하드 룰 발동 (손절·트레일링·기간 만료·Protections) → 매니저 의견과 무관하게 집행.

### 12-3. 투자 메모 스키마

이 흐름을 LLM이 건너뛰지 못하게 하려면 출력 스키마가 단계를 강제해야 한다. `schemas.InvestmentMemo`를 추가했다. 필수 필드가 비면 구조화 출력이 실패하고, 실패하면 REVIEW로 격리된다. 즉 "촉매 없이 산다", "하락 시나리오 없이 산다"가 스키마 수준에서 막힌다.

```
InvestmentMemo
  business_summary      사업 두 문장
  thesis                왜 지금 이 가격이 틀렸나
  bull_case / bear_case 양쪽 케이스
  valuation_basis       어떤 배수·방법으로 봤나
  price_target, downside_price   → upside_pct, downside_pct, reward_risk 자동 계산
  catalysts[]           촉매와 예상 시점
  invalidation[]        논지가 깨지는 사실 조건
  rating                5단계
  conviction            0~1
  sizing_pct            권고 비중 (하드 룰이 클램프)
  exit_plan             목표 도달·논지 깨짐·기간 만료 시 각각 어떻게
  time_horizon
```

`reward_risk < 2`이면 Buy/Overweight를 거부하는 검증기를 넣었다. 매니저 기준 2번을 코드로 내린 것이다.

### 12-4. 일반인 사용자에게 보여줄 것

운용사 없이 쓰는 사람이 신뢰할 수 있어야 하므로, 대시보드 종목 상세(기획서 화면 4)에 투자 메모를 **매니저가 쓴 것처럼** 그대로 보여준다: 사업 요약 → 논지 → 상승/하락 시나리오와 비율 → 촉매 → 깨지는 조건 → 등급·비중 → 매도 계획. 결정 큐에는 매도 사유(12-2의 1~7 중 어느 것)를 배지로 표시한다. 기획서 화면 3·4에 이 항목을 반영한다.
