# 4차 실측 — 유니버스 편향 (고정 40종목 vs 시점 지수 구성)

작성 2026-11-13, core 워커. 숫자만 적는다. 기본값이나 권장은 정하지 않는다.
US 부분만 있다. KRX(KOSPI200) 부분은 구성종목 데이터 소스가 정해지지 않아 비어 있다(§4).

## 1. 무엇을 바꿨나

- 2 · 3차 실측의 후보는 **지금 고른 고정 40종목**이다. 기간 중 지수에서 빠지거나 상장폐지된 종목은 처음부터 후보에 없다(생존 편향).
- 4차는 리밸런스마다 **그날의 지수 구성**(`universe.members_on`)을 후보로 쓴다. 후보 = 그날 구성 ∩ 그날까지 시세가 있는 종목. 선별 규칙 · 하드 룰 · 비용은 3차와 같다(`RiskConfig` · `ScreenConfig` · `MARKETS` 값 변경 없음).
- 편출된 종목: 보유는 유지하고 규칙 청산(손절 · 트레일링 · 만료 · 등급 하향)만 받는다. 다시 사지 않는다.
- 시세가 끊긴 보유 종목: 첫 빈 날에 마지막 종가(− 슬리피지 0.05%)로 `delisted` 청산.

## 4. KRX (KOSPI200) — 막힘: 사용자 결정 대기 (KRX 로그인 수동 CSV vs 미제공)

- KOSPI200 시점 구성 데이터가 없다. 구성 · 변경 이력을 주는 곳으로 확인된 것은 KRX 정보데이터시스템 [11006](로그인 필요)뿐이고, KIS · KRX Open API · 공공데이터포털 API에서는 확인 안 됨(조사표: `.claude/handoff/REPORT-universe-history.md`).
- `scripts/build_universe.py`는 `data/external/krx_11006_kospi200_YYYYMMDD.csv`가 생기면 `kospi200_history.csv`를 만든다(지금은 건너뜀).
- `^KS11` 2026-07-31 +17.9% 교차 확인(docs/00 §4)도 아직 안 했다.

`yahoo._cache_is_fresh`는 오늘 쓴 캐시만 인정하므로 **날짜가 바뀐 실행은 전 종목(약 560 + 지수)을 다시 받아 캐시를 덮어쓴다**. 수정주가(`auto_adjust=True`)라 배당 · 분할 반영으로 과거 가격이 바뀌어 다른 날 재실행 수치가 조금 달라질 수 있고, Yahoo 응답이 바뀌면 못 받는 종목 수도 달라질 수 있다. `summary.json`의 `not_cached_today`는 "실행 전 캐시가 오늘 것이 아니었고 읽기에 성공한 종목 수"다(실패한 종목은 `failed`에만 들어간다).
